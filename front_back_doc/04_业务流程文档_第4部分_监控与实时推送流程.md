# 业务流程文档（第4部分）：监控与实时推送流程

## 1. 文档目标
- 说明监控数据从后端聚合到前端展示的流程。
- 说明 REST 查询与 WebSocket 实时推送两条链路如何协同。

## 2. 涉及模块
- 监控接口：`MonitoringController`
- 指标聚合：`MonitoringService`
- 实时推送：`TelemetryPushService`
- WebSocket 配置：`WebSocketConfig`
- 数据模型：`SystemHealth`、`TaskMetrics`、`GpuMetrics`、`TelemetrySnapshot`

## 3. 监控查询流程（REST）

### 3.1 健康检查流程
1. 前端调用 `GET /api/health`。
2. `MonitoringController.health()` 进入 `MonitoringService.getSystemHealth()`。
3. 服务层聚合：
- DB 连通性（`gpuMapper.selectCount`）
- Redis 连通性（`ping`）
- 熔断器状态（`CircuitBreakerService.getState()`）
- 队列最老任务等待时间（优先队列 + `gpu_task.enqueue_at`）
4. 返回 `SystemHealth`：`status/dbStatus/redisStatus/schedulerStatus/circuitBreakerState/oldestQueuedTaskSeconds`。

### 3.2 聚合指标流程
1. 前端调用 `GET /api/metrics`。
2. `MonitoringController.metrics()` 分别取：
- `MonitoringService.getTaskMetrics()`
- `MonitoringService.getGpuMetrics()`
3. 组合返回：`{ tasks, gpus }`。

## 4. 指标计算规则（核心）

### 4.1 TaskMetrics 计算
- `queueLength`：来自 `TaskPriorityQueue.size()`。
- `taskCountByStatus`：按 `TaskStatus` 聚合计数。
- `queueLengthByPriority`：仅 `QUEUED` 任务，按优先级桶分组。
- `avgWaitSecondsByPriority`：`now - enqueueAt` 的均值。
- `dispatchLatencyPercentilesSeconds`：p50/p95/p99。
- `completionRate/failureRate`：基于终态任务统计得到百分比字符串。
- `retryQueueSize/dlqSize`：来自 `TaskRetryDlqService`。
- `webhookRetryQueueSize`：来自 `TaskNotificationService`。

### 4.2 GpuMetrics 计算
- `countByStatus`：按 `GpuStatus` 聚合计数。
- `utilizationRate`：`Busy / Total` 百分比字符串。
- `usedMemoryGbByGpu/remainingMemoryGbByGpu`：基于运行任务与 GPU 显存计算。
- `vramFragmentationByGpu`：`1 - minMemoryGb / gpu.memoryGb`（Busy 且有运行任务时）。
- `idleSecondsByGpu`：空闲 GPU 距离最近完成任务的秒数。

## 5. 实时推送流程（WebSocket）

### 5.1 连接与订阅
1. 前端连接 STOMP 端点：`/ws`（支持 SockJS）。
2. 订阅主题：
- 监控大盘：`/topic/telemetry`
- 任务状态：`/topic/task-status/{userId}`（由通知服务推送）

### 5.2 遥测推送
1. `TelemetryPushService.pushTelemetry()` 定时执行：
- 初始延迟：`telemetry.initial-delay-ms`（默认 5000ms）
- 推送间隔：`telemetry.push-interval-ms`（默认 3000ms）
2. 每次推送构建 `TelemetrySnapshot`：
- `timestamp`
- `health`（SystemHealth）
- `tasks`（TaskMetrics）
- `gpus`（GpuMetrics）
3. 通过 `SimpMessagingTemplate.convertAndSend(telemetryTopic, snapshot)` 发布。

## 6. 页面与接口关系
- 监控总览页初始化：先拉取 `GET /api/metrics` 与 `GET /api/health`。
- 监控总览页增量更新：订阅 `/topic/telemetry`。
- 任务详情页状态变化：订阅 `/topic/task-status/{userId}`。

## 7. 权限与访问控制
- `/api/health`、`/api/metrics` 需要 `ROLE_ADMIN` 或 `monitoring:read`。
- WebSocket 连接端点在安全配置中放行（`/ws/**`）。
- 监控 REST 与 WebSocket 结合时，前端仍需自行处理未授权场景回退。

## 8. 异常与边界
- 遥测推送异常被捕获并记录，不会中断主业务流程。
- `utilizationRate/completionRate/failureRate` 为字符串百分比，图表计算前需转数值。
- Redis/DB 异常时 `SystemHealth.status` 可能降为 `DOWN` 或 `DEGRADED`。
- 若任务/资源数据为空，监控返回空集合或零值，不代表接口异常。
