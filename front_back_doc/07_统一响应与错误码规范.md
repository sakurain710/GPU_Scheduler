# 统一响应与错误码规范

## 1. 文档目标
- 统一前后端响应结构约定。
- 给出当前代码中全部已落地错误码与来源。
- 明确前端错误处理优先级与兼容策略。

## 2. 标准响应结构

### 2.1 基础结构（Result<T>）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| code | Integer | 是 | 业务状态码（通常与HTTP语义一致） |
| errorCode | String | 否 | 业务错误码（用于前端分支） |
| message | String | 是 | 提示信息 |
| data | Any | 否 | 业务数据；无数据时为 `null` |

### 2.2 成功响应约定
- 默认成功：`code=200`、`message=操作成功`
- 可自定义成功消息：`Result.success(message, data)`

### 2.3 失败响应约定
- 推荐使用：`Result.error(code, errorCode, message)`
- 保留兼容：`Result.error(code, message)`（无 `errorCode`）

## 3. 错误码来源分层

### 3.1 BusinessException 系列（主渠道）
- 由 `GlobalExceptionHandler.handleBusinessException` 统一输出：
- `code = ex.httpStatus`
- `errorCode = ex.code`
- `message = ex.message`

### 3.2 安全过滤器与认证入口
- `JwtAuthenticationEntryPoint`：`AUTH_UNAUTHORIZED`
- `JwtAuthenticationFilter`：`AUTH_TOKEN_TYPE_INVALID`
- `RateLimitFilter`：`RATE_LIMIT_EXCEEDED`、`AUTH_RATE_LIMIT_BACKEND_UNAVAILABLE`
- `IdempotencyFilter`：`IDEMPOTENCY_CONFLICT`

### 3.3 兜底异常
- 参数校验异常、权限异常、认证异常、系统异常等部分路径目前可能不带 `errorCode`。

## 4. 错误码清单（当前实现）

| errorCode | HTTP(code) | 典型message | 主要来源 |
|---|---:|---|---|
| AUTH_UNAUTHORIZED | 401 | 未授权访问，请先登录 | `JwtAuthenticationEntryPoint` |
| AUTH_TOKEN_TYPE_INVALID | 401 | 令牌类型错误 | `JwtAuthenticationFilter` |
| RATE_LIMIT_EXCEEDED | 429 | 请求过于频繁，请稍后重试 | `RateLimitFilter` / `RateLimitException` |
| AUTH_RATE_LIMIT_BACKEND_UNAVAILABLE | 503 | 认证服务限流后端不可用，请稍后重试 | `RateLimitFilter` |
| IDEMPOTENCY_CONFLICT | 409 | X-Request-Id重复且请求内容不一致 | `IdempotencyFilter` |
| INVALID_TOKEN | 401 | 无效的刷新令牌/令牌类型错误等 | `InvalidTokenException` |
| INVALID_CREDENTIALS | 401 | 自定义凭证错误消息 | `InvalidCredentialsException` |
| USER_DISABLED | 403 | 用户已被禁用 | `UserDisabledException` |
| RESOURCE_NOT_FOUND | 404 | 资源不存在（含用户/角色/GPU/任务） | `ResourceNotFoundException` |
| DUPLICATE_RESOURCE | 409 | 用户名已存在/邮箱已被使用/角色编码已存在 | `DuplicateResourceException` |
| INVALID_TASK_STATE | 409 | 非法状态转换 | `InvalidTaskStateException` |
| INVALID_TASK_ID | 400 | taskId must be a positive number | `OpsController` 直接抛出 |
| GPU_ALREADY_ASSIGNED | 409 | GPU已被其他调度线程占用 | `TaskAssignmentService` |
| GPU_BUSY | 400 | GPU正在执行任务，不允许删除/修改状态 | `GpuService` |

| TASK_ACTIVE_LIMIT_EXCEEDED | 429 | Active task limit exceeded... | `GpuTaskService` |

| ROLE_IN_USE | 400 | 该角色下还有用户，无法删除 | `RoleService` |

## 5. 无 errorCode 的错误路径（现状）

| 场景 | code | message | 备注 |
|---|---:|---|---|
| AuthenticationException | 401 | 用户名或密码错误/账户已被禁用/未提供有效认证凭证 | `GlobalExceptionHandler` 当前未设置 `errorCode` |
| AccessDeniedException | 403 | 权限不足，无法访问该资源 | `GlobalExceptionHandler` 当前未设置 `errorCode` |
| MethodArgumentNotValidException | 400 | 参数校验失败 | `data` 为字段错误Map，未设置 `errorCode` |
| Exception(兜底) | 500 | 系统内部错误，请稍后重试 | 未设置 `errorCode` |

## 6. 前端处理规范

### 6.1 处理优先级
1. 先看 `code` 判定大类（401/403/409/429/5xx）。
2. 再看 `errorCode` 做精细分支。
3. 最后回退到 `message` 文案展示。

### 6.2 建议分支
- `401 + AUTH_UNAUTHORIZED/INVALID_TOKEN/AUTH_TOKEN_TYPE_INVALID`：清理会话并跳转登录。
- `403 + TASK_FORBIDDEN/USER_DISABLED`：提示无权限或账户状态异常。
- `409 + IDEMPOTENCY_CONFLICT/INVALID_TASK_STATE/DUPLICATE_RESOURCE`：提示并阻止重复操作。
- `429 + RATE_LIMIT_EXCEEDED/TASK_ACTIVE_LIMIT_EXCEEDED`：节流提示，按 `Retry-After`（如有）重试。
- `503 + AUTH_RATE_LIMIT_BACKEND_UNAVAILABLE`：提示认证链路暂不可用。

### 6.3 写操作建议
- 对 `POST/PUT/DELETE` 请求携带 `X-Request-Id`，保证幂等冲突可识别。

## 7. 一致性约束（联调）
- 推荐所有失败响应都携带 `errorCode`。
- 历史/框架异常不带 `errorCode` 时，前端需兼容。
- `code` 与 HTTP 状态应保持语义一致。

## 8. 待确认项
- 是否将 `GlobalExceptionHandler` 的 `AuthenticationException`、`AccessDeniedException`、`MethodArgumentNotValidException` 统一补齐 `errorCode`。
- 是否制定错误码命名前缀规范（如 `AUTH_*`, `TASK_*`, `GPU_*`）并限制新增来源。
