# 页面功能结构与交互说明（第3部分）：GPU资源管理与运维操作台

## 1. 文档范围
- 本部分覆盖页面模块：
1. GPU资源列表与详情页
2. GPU注册与状态维护弹窗/页
3. GPU健康与利用率看板
4. 运维操作台（调度、DLQ、强制处置）
- 仅描述功能结构与交互行为，不包含视觉设计。

## 2. 页面模块一：GPU资源列表与详情（GPU Inventory）

### 2.1 页面结构（功能区域）
- 筛选区：状态筛选、排序字段、排序方向
- 列表区：GPU表格（型号、厂商、显存、算力、状态）
- 分页区：页码/每页条数
- 行操作区：查看详情、修改状态、删除

### 2.2 展示数据来源
- `GET /api/gpus`
- `GET /api/gpus/{gpuId}`

### 2.3 操作行为
1. 页面初始化加载 GPU 分页列表。
2. 用户调整筛选/排序参数后刷新列表。
3. 点击行查看详情，展示完整 `GpuResponse`。
4. 根据权限与状态控制行操作可见性。

### 2.4 状态变化
- `loading` -> `loaded`
- `loaded` -> `filtering` -> `loaded`
- `loaded` -> `detail_loading` -> `detail_ready`

### 2.5 接口依赖
- `GET /api/gpus?page&size&status&sortBy&sortDir`
- `GET /api/gpus/{gpuId}`

## 3. 页面模块二：GPU注册与状态维护（GPU Edit Actions）

### 3.1 页面结构（功能区域）
- 注册表单区：`name/manufacturer/memoryGb/computingPowerTflops/remark`
- 状态更新区：目标状态选择（1~4）
- 删除确认区：删除前二次确认
- 反馈区：成功/失败提示

### 3.2 展示数据来源
- 注册请求与状态更新请求的本地表单模型
- 后端响应 `GpuResponse`

### 3.3 操作行为
1. 注册：调用 `POST /api/gpus`。
2. 更新状态：调用 `PUT /api/gpus/{gpuId}/status`。
3. 删除：调用 `DELETE /api/gpus/{gpuId}`。
4. BUSY GPU 尝试更新/删除时展示后端返回的禁止信息。

### 3.4 状态变化
- `editing` -> `submitting` -> `success`
- `editing` -> `submitting` -> `error`
- `deleting` -> `deleted` 或 `delete_failed`

### 3.5 接口依赖
- `POST /api/gpus`
- `PUT /api/gpus/{gpuId}/status`
- `DELETE /api/gpus/{gpuId}`
- 典型错误：`GPU_BUSY`、`RESOURCE_NOT_FOUND`

## 4. 页面模块三：GPU健康与利用率看板（GPU Health Panel）

### 4.1 页面结构（功能区域）
- 状态分布区：Idle/Busy/Offline/Maintenance 数量
- 利用率区：总数、Busy、Idle、利用率百分比
- 操作区：刷新、心跳上报入口（可选）

### 4.2 展示数据来源
- `GET /api/gpus/health`（状态计数）
- `GET /api/gpus/metrics`（利用率摘要）

### 4.3 操作行为
1. 页面加载并行拉取健康与利用率数据。
2. 支持手动刷新。
3. 对指定 GPU 上报心跳（管理员/heartbeat 权限）。

### 4.4 状态变化
- `panel_loading` -> `panel_ready`
- `panel_ready` -> `refreshing` -> `panel_ready`
- `heartbeat_submitting` -> `heartbeat_done`

### 4.5 接口依赖
- `GET /api/gpus/health`
- `GET /api/gpus/metrics`
- `POST /api/gpus/{gpuId}/heartbeat`

## 5. 页面模块四：运维操作台（Ops Console）

### 5.1 页面结构（功能区域）
- 调度控制区：暂停/恢复、状态显示
- 熔断控制区：查看状态并重置
- DLQ管理区：查看列表、清空、单任务回放
- 任务强制处置区：强制重入队、强制失败、抢占、清空排队
- 通知重试区：webhook 重试队列长度

### 5.2 展示数据来源
- 调度器状态：`GET /api/ops/dispatcher/status`
- DLQ 列表：`GET /api/ops/dlq`
- 通知重试：`GET /api/ops/notification/webhook/retry/status`

### 5.3 操作行为
1. 暂停/恢复调度：`POST /dispatcher/pause`、`/dispatcher/resume`。
2. 熔断器重置：`POST /circuit-breaker/reset`。
3. DLQ 操作：清空、指定任务回放。
4. 任务处置：
- 强制重入队 `/tasks/{id}/force-requeue`
- 强制失败 `/tasks/{id}/force-fail`
- 抢占 `/tasks/{id}/preempt`
- 清空排队 `/queue/drain`

### 5.4 状态变化
- `ops_idle` -> `action_running` -> `action_done`
- `ops_idle` -> `action_running` -> `action_failed`
- `dlq_loading` -> `dlq_ready`

### 5.5 接口依赖
- `POST /api/ops/dispatcher/pause`
- `POST /api/ops/dispatcher/resume`
- `GET /api/ops/dispatcher/status`
- `POST /api/ops/circuit-breaker/reset`
- `GET /api/ops/dlq`
- `POST /api/ops/dlq/clear`
- `POST /api/ops/dlq/{taskId}/reprocess`
- `POST /api/ops/tasks/{taskId}/force-requeue`
- `POST /api/ops/tasks/{taskId}/force-fail`
- `POST /api/ops/tasks/{taskId}/preempt`
- `POST /api/ops/queue/drain`
- `GET /api/ops/notification/webhook/retry/status`

## 6. 跨页面交互规则（GPU/运维域）
- 前端统一使用路径前缀：`/api/gpus`。
- GPU列表与运维操作台共享任务/资源状态源，操作后应联动刷新。
- 对“强制类”操作需强制二次确认并展示影响说明。

## 7. 已确认与待确认项
- 是否为 GPU 心跳上报提供批量操作入口（当前后端仅单 GPU 上报）。
- 不引入“运维只读角色”，运维操作仍统一要求 `ops:manage` / `ROLE_ADMIN`。
