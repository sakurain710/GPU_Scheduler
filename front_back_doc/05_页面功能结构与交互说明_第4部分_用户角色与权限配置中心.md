# 页面功能结构与交互说明（第4部分）：用户、角色与权限配置中心

## 1. 文档范围
- 本部分覆盖页面模块：
1. 用户管理页
2. 角色管理页
3. 权限配置页（资源/权限字典）
4. 授权关系编辑弹窗（用户-角色、角色-权限、角色-用户）
- 仅描述功能结构与交互行为，不包含视觉设计。

## 2. 页面模块一：用户管理页（User Admin）

### 2.1 页面结构（功能区域）
- 检索区：用户名、邮箱、状态、排序
- 列表区：用户表格（用户名、邮箱、状态、角色、时间）
- 行操作区：详情、编辑、删除、分配角色
- 弹窗区：创建用户/编辑用户/分配角色

### 2.2 展示数据来源
- `GET /api/users`（分页列表）
- `GET /api/users/{userId}`（详情）

### 2.3 操作行为
1. 新建用户：`POST /api/users`。
2. 更新用户：`PUT /api/users/{userId}`。
3. 删除用户：`DELETE /api/users/{userId}`。
4. 分配角色：`POST /api/users/{userId}/roles`。

### 2.4 状态变化
- `list_loading` -> `list_ready`
- `editing` -> `saving` -> `saved`
- `assigning_roles` -> `assigned`

### 2.5 接口依赖
- `GET /api/users`
- `GET /api/users/{userId}`
- `POST /api/users`
- `PUT /api/users/{userId}`
- `DELETE /api/users/{userId}`
- `POST /api/users/{userId}/roles`

## 3. 页面模块二：角色管理页（Role Admin）

### 3.1 页面结构（功能区域）
- 列表区：角色表格（编码、名称、类型、状态、权限数）
- 行操作区：编辑、删除、权限配置、用户绑定
- 弹窗区：新建角色/编辑角色

### 3.2 展示数据来源
- `GET /api/roles`
- `GET /api/roles/{roleId}`

### 3.3 操作行为
1. 创建角色：`POST /api/roles`（可附初始权限）。
2. 更新角色：`PUT /api/roles/{roleId}`。
3. 删除角色：`DELETE /api/roles/{roleId}`。
4. 配置权限：`POST /api/roles/{roleId}/permissions` 或 `DELETE /.../permissions`。
5. 绑定用户：`POST /api/roles/{roleId}/users`。
6. 解绑用户：`DELETE /api/roles/{roleId}/users`。

### 3.4 状态变化
- `role_list_loading` -> `role_list_ready`
- `role_editing` -> `role_saving` -> `role_saved`
- `permission_binding` -> `permission_bound`

### 3.5 接口依赖
- `GET /api/roles`
- `GET /api/roles/{roleId}`
- `POST /api/roles`
- `PUT /api/roles/{roleId}`
- `DELETE /api/roles/{roleId}`
- `POST /api/roles/{roleId}/permissions`
- `DELETE /api/roles/{roleId}/permissions`
- `POST /api/roles/{roleId}/users`
- `DELETE /api/roles/{roleId}/users`

## 4. 页面模块三：权限配置页（RBAC Dictionary）

### 4.1 页面结构（功能区域）
- 资源树区：资源层级（菜单/API/按钮/数据）
- 权限列表区：按资源过滤权限项
- 过滤区：`status/type/resourceId`

### 4.2 展示数据来源
- `GET /api/rbac/resources`
- `GET /api/rbac/permissions`

### 4.3 操作行为
1. 加载资源树（默认启用状态）。
2. 选择资源节点后查询对应权限。
3. 在角色授权弹窗中复用该字典数据作为可选项。

### 4.4 状态变化
- `dict_loading` -> `dict_ready`
- `resource_selecting` -> `permission_loading` -> `permission_ready`

### 4.5 接口依赖
- `GET /api/rbac/resources?parentId&type&status`
- `GET /api/rbac/permissions?resourceId&status`

## 5. 页面模块四：授权关系编辑弹窗

### 5.1 用户-角色绑定弹窗
- 目标：为指定用户配置角色集合。
- 提交接口：`POST /api/users/{userId}/roles`
- 交互要点：提交前展示“将覆盖用户现有角色”的确认。

### 5.2 角色-权限绑定弹窗
- 目标：为角色配置权限集合。
- 提交接口：`POST /api/roles/{roleId}/permissions`
- 交互要点：该接口为“覆盖写入”，提交需包含完整目标权限集。

### 5.3 角色-用户绑定弹窗
- 目标：把多个用户绑定到角色（可选过期时间）。
- 提交接口：`POST /api/roles/{roleId}/users`
- 交互要点：属于新增绑定；解除需走 `DELETE /users`。

## 6. 跨页面交互规则（RBAC域）
- 授权变更后建议刷新当前用户上下文和菜单缓存。
- 角色/权限配置页应按权限码渲染入口，兼容角色门禁。
- 错误处理优先读取 `errorCode`：如 `ROLE_IN_USE`、`RESOURCE_NOT_FOUND`、`DUPLICATE_RESOURCE`。

## 7. 状态与生效说明
- 后端每次请求会实时加载用户角色与权限码。
- 因此授权变更在后续请求可即时生效，不要求强制重新登录。
- 前端若做本地权限缓存，需在授权变更后主动刷新。

## 8. 已确认项
- 角色页“权限差异预览”暂不作为本轮必需能力。
- 不引入 RBAC 只读角色，角色与权限修改入口继续使用管理权限控制。
- `AssignUsersRequest/AssignPermissionsRequest` 的 `roleId` 一致性由前端执行强校验，后端以路径参数为准。
