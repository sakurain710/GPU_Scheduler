# 接口文档（第1部分）：认证接口

## 1. 文档范围
- 控制器：`AuthController`
- 路径前缀：`/api/auth`
- 覆盖接口：`/login`、`/refresh`、`/logout`、`/me`
- 本文只描述已在代码中实现的行为。

## 2. 通用约定

### 2.1 统一响应结构（Result）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| code | Integer | 业务状态码 | 否 | 成功时 `200` |
| errorCode | String | 业务错误码（用于前端分支处理） | 是 | `null` |
| message | String | 响应消息 | 否 | 成功时通常为`操作成功` |
| data | Object | 业务数据 | 是 | `null` |

### 2.2 公共请求头

| Header | 说明 | 必填 |
|---|---|---|
| Content-Type: application/json | JSON 请求体 | `POST` 接口是 |
| Authorization: Bearer <token> | 访问令牌 | `/logout`、`/me` 实际需要 |
| X-Request-Id | 幂等键（防重复提交） | 否（建议 `POST` 提供） |

### 2.3 认证相关错误码（本部分可能出现）

| HTTP | errorCode | 触发场景 |
|---|---|---|
| 400 | `null` | 请求参数校验失败（如字段为空） |
| 401 | `AUTH_UNAUTHORIZED` | 进入认证入口点时未授权 |
| 401 | `INVALID_TOKEN` | token 无效/类型错误/缺失等业务校验失败 |
| 429 | `RATE_LIMIT_EXCEEDED` | 限流触发 |
| 503 | `AUTH_RATE_LIMIT_BACKEND_UNAVAILABLE` | 认证接口限流后端不可用（fail-closed） |

## 3. 接口明细

---

### 3.1 用户登录
- **方法**：`POST`
- **路径**：`/api/auth/login`
- **鉴权**：否

#### 请求体

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| username | String | 用户名 | 否 | 无 | `@NotBlank` |
| password | String | 密码 | 否 | 无 | `@NotBlank` |

#### 成功响应 `data`（LoginResponse）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| accessToken | String | 访问令牌 | 否 | 无 | JWT |
| refreshToken | String | 刷新令牌 | 否 | 无 | JWT |
| tokenType | String | 令牌类型 | 否 | `Bearer` | 固定值 `Bearer` |
| expiresIn | Long | accessToken 有效秒数 | 否 | `86400` | 正整数 |
| userId | Long | 用户ID | 否 | 无 | 正整数 |
| username | String | 用户名 | 否 | 无 | - |
| roles | List<String> | 角色编码列表 | 否 | `[]` | 例如 `ROLE_ADMIN` |

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "accessToken": "<ACCESS_TOKEN>",
    "refreshToken": "<REFRESH_TOKEN>",
    "tokenType": "Bearer",
    "expiresIn": 86400,
    "userId": 1,
    "username": "alice",
    "roles": ["ROLE_ADMIN"]
  }
}
```

#### 失败示例（账号密码错误）
```json
{
  "code": 401,
  "errorCode": null,
  "message": "用户名或密码错误",
  "data": null
}
```

---

### 3.2 刷新访问令牌
- **方法**：`POST`
- **路径**：`/api/auth/refresh`
- **鉴权**：否（通过 refreshToken 校验）

#### 请求体

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| refreshToken | String | 刷新令牌 | 否 | 无 | `@NotBlank` |

#### 成功响应 `data`
- 与 `3.1` 的 `LoginResponse` 字段一致。

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "accessToken": "<NEW_ACCESS_TOKEN>",
    "refreshToken": "<NEW_REFRESH_TOKEN>",
    "tokenType": "Bearer",
    "expiresIn": 86400,
    "userId": 1,
    "username": "alice",
    "roles": ["ROLE_ADMIN"]
  }
}
```

#### 失败示例（refreshToken 无效）
```json
{
  "code": 401,
  "errorCode": "INVALID_TOKEN",
  "message": "无效的刷新令牌",
  "data": null
}
```

---

### 3.3 用户登出
- **方法**：`POST`
- **路径**：`/api/auth/logout`
- **鉴权**：路径级 `permitAll`，但业务上需要 `accessToken` 或 `refreshToken` 至少一个

#### 请求头
- 推荐提供：`Authorization: Bearer <accessToken>`

#### 请求体（可选）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| refreshToken | String | 可选刷新令牌（提供则一并拉黑） | 是 | `null` | JWT |

#### 成功响应
- `data` 固定为 `null`。

```json
{
  "code": 200,
  "errorCode": null,
  "message": "登出成功",
  "data": null
}
```

#### 失败示例（未提供任何可用令牌）
```json
{
  "code": 401,
  "errorCode": "INVALID_TOKEN",
  "message": "缺少登出令牌",
  "data": null
}
```

---

### 3.4 获取当前用户
- **方法**：`GET`
- **路径**：`/api/auth/me`
- **鉴权**：路径级 `permitAll`，但业务上需要有效 `accessToken`

#### 请求头
- 必填：`Authorization: Bearer <accessToken>`

#### 成功响应 `data`（UserResponse）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| id | Long | 用户ID | 否 | 无 | 正整数 |
| username | String | 用户名 | 否 | 无 | - |
| email | String | 邮箱 | 是 | `null` | 邮箱格式由写入端保证 |
| status | Integer | 账号状态 | 否 | 无 | `1`启用；其他值为非启用状态 |
| roles | List<String> | 角色编码列表 | 否 | `[]` | 例如 `ROLE_ADMIN` |
| createdAt | LocalDateTime | 创建时间 | 否 | 无 | `yyyy-MM-dd HH:mm:ss`（Asia/Shanghai） |
| updatedAt | LocalDateTime | 更新时间 | 否 | 无 | `yyyy-MM-dd HH:mm:ss`（Asia/Shanghai） |

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "id": 1,
    "username": "alice",
    "email": "alice@example.com",
    "status": 1,
    "roles": ["ROLE_ADMIN"],
    "createdAt": "2026-03-31T10:20:30",
    "updatedAt": "2026-04-03T09:00:00"
  }
}
```

#### 失败示例（未登录）
```json
{
  "code": 401,
  "errorCode": "INVALID_TOKEN",
  "message": "用户未登录",
  "data": null
}
```

## 4. 与前端联调注意事项
- `POST` 请求建议携带 `X-Request-Id`，避免重复提交导致语义不一致。
- 前端错误处理应优先判断 `errorCode`，其次再看 `message`。
- `/api/auth/me` 与 `/api/auth/logout` 虽位于 `permitAll` 前缀下，但实际需要 token 才能得到业务成功响应。
