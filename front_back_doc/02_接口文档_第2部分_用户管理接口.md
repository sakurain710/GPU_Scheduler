# 接口文档（第2部分）：用户管理接口

## 1. 文档范围
- 控制器：`UserController`
- 路径前缀：`/api/users`
- 覆盖接口：创建、更新、删除、详情、分页列表、分配角色

## 2. 访问控制与通用约定

### 2.1 权限要求
- 控制器级鉴权：`hasAnyAuthority('ROLE_ADMIN','user:manage')`
- 未认证：返回 `401`
- 无权限：返回 `403`

### 2.2 统一响应结构（Result）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| code | Integer | 业务状态码 | 否 | 成功时 `200` |
| errorCode | String | 业务错误码 | 是 | `null` |
| message | String | 响应消息 | 否 | 成功时通常为`操作成功` |
| data | Object | 业务数据 | 是 | `null` |

### 2.3 常见错误码

| HTTP | errorCode | 场景 |
|---|---|---|
| 400 | `null` | 参数校验失败（如邮箱格式错误） |
| 401 | `AUTH_UNAUTHORIZED` | 未登录访问受保护资源 |
| 403 | `null` | 权限不足 |
| 404 | `RESOURCE_NOT_FOUND` | 用户/角色不存在 |
| 409 | `DUPLICATE_RESOURCE` | 用户名或邮箱冲突 |

## 3. 接口明细

---

### 3.1 创建用户
- **方法**：`POST`
- **路径**：`/api/users`
- **鉴权**：是

#### 请求体（CreateUserRequest）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| username | String | 用户名 | 否 | 无 | `@NotBlank`, 长度 `3-50` |
| password | String | 密码 | 否 | 无 | `@NotBlank`, 长度 `6-100` |
| email | String | 邮箱 | 否 | 无 | `@NotBlank`, `@Email` |
| status | Integer | 用户状态 | 是 | `1` | `0=禁用,1=启用` |

#### 成功响应 `data`（UserResponse）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| id | Long | 用户ID | 否 | 无 |
| username | String | 用户名 | 否 | 无 |
| email | String | 邮箱 | 是 | `null` |
| status | Integer | 用户状态 | 否 | 无 |
| roles | List<String> | 角色编码列表 | 否 | `[]` |
| createdAt | LocalDateTime | 创建时间 | 否 | 无 |
| updatedAt | LocalDateTime | 更新时间 | 否 | 无 |

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "id": 12,
    "username": "alice",
    "email": "alice@example.com",
    "status": 1,
    "roles": [],
    "createdAt": "2026-04-03T10:00:00",
    "updatedAt": "2026-04-03T10:00:00"
  }
}
```

#### 失败示例（用户名已存在）
```json
{
  "code": 409,
  "errorCode": "DUPLICATE_RESOURCE",
  "message": "用户名已存在",
  "data": null
}
```

### 3.2 更新用户
- **方法**：`PUT`
- **路径**：`/api/users/{userId}`
- **鉴权**：是

#### 路径参数

| 字段 | 类型 | 含义 | 可空 |
|---|---|---|---|
| userId | Long | 用户ID | 否 |

#### 请求体（UpdateUserRequest）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| email | String | 邮箱 | 是 | `null` | `@Email` |
| status | Integer | 用户状态 | 是 | `null` | `0=禁用,1=启用` |

#### 行为说明
- 仅更新传入字段。
- 若更新邮箱且与其他用户冲突，返回 `409`。

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "id": 12,
    "username": "alice",
    "email": "alice_new@example.com",
    "status": 1,
    "roles": ["ROLE_USER"],
    "createdAt": "2026-04-03T10:00:00",
    "updatedAt": "2026-04-03T10:30:00"
  }
}
```

### 3.5 用户分页列表
- **方法**：`GET`
- **路径**：`/api/users`
- **鉴权**：是

#### 查询参数

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| page | Integer | 页码（从1开始） | 是 | `1` | `@Min(1)` |
| size | Integer | 每页数量 | 是 | `10` | `@Min(1)`, `@Max(200)` |
| username | String | 用户名模糊过滤 | 是 | `null` | - |
| email | String | 邮箱模糊过滤 | 是 | `null` | - |
| status | Integer | 状态过滤 | 是 | `null` | `0/1` |
| sortBy | String | 排序字段 | 是 | `createdAt` | `createdAt/username/email/status/id` |
| sortDir | String | 排序方向 | 是 | `desc` | `asc/desc` |

#### 成功响应 `data`（IPage<UserResponse>）

| 字段 | 类型 | 含义 |
|---|---|---|
| records | List<UserResponse> | 当前页数据 |
| total | Long | 总记录数 |
| size | Long | 每页大小 |
| current | Long | 当前页码 |
| pages | Long | 总页数 |

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "records": [
      {
        "id": 1,
        "username": "admin",
        "email": "admin@example.com",
        "status": 1,
        "roles": ["ROLE_ADMIN"],
        "createdAt": "2026-03-01T08:00:00",
        "updatedAt": "2026-04-03T09:00:00"
      }
    ],
    "total": 1,
    "size": 10,
    "current": 1,
    "pages": 1
  }
}
```

### 3.6 为用户分配角色
- **方法**：`POST`
- **路径**：`/api/users/{userId}/roles`
- **鉴权**：是

#### 路径参数

| 字段 | 类型 | 含义 | 可空 |
|---|---|---|---|
| userId | Long | 用户ID | 否 |

#### 请求体
- 类型：`List<Long>`（角色ID数组）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| body | List<Long> | 角色ID集合 | 是 | `null` |

#### 查询参数

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| expiresAt | LocalDateTime | 角色过期时间 | 是 | `null` |

#### 行为说明
- 先清空该用户已有角色，再按 `roleIds` 重建绑定。
- `roleIds` 为空或不传时，结果为“清空角色”。
- 任一角色ID不存在时，返回 `404`。

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": null
}
```

#### 失败示例（角色不存在）
```json
{
  "code": 404,
  "errorCode": "RESOURCE_NOT_FOUND",
  "message": "角色不存在: 999",
  "data": null
}
```

## 4. 联调注意事项
- `assignRoles` 是覆盖写入语义，不是增量追加。
- 时间字段 `createdAt/updatedAt/expiresAt` 的序列化格式依赖全局 Jackson 配置：`⚠️ 待确认`。
- 列表接口排序字段超出允许集合时会回退到 `createdAt` 排序。
