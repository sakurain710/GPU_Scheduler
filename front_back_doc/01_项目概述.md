# 项目概述

## 文档范围
- 本文档用于前后端联调阶段的项目级认知对齐，不包含接口字段级细节。

## 系统定位
- 系统名称：`gpu-scheduler`（Spring Boot 后端）。
- 系统目标：管理 GPU 资源并提供任务提交、排队调度、状态流转、审批、运维与监控能力。
- 对外服务形态：REST API + WebSocket 推送。

### 能力现状
- `✅ 已实现` JWT 登录认证、刷新、登出、当前用户查询（`/api/auth/*`）。
- `✅ 已实现` 任务提交流程与状态机流转（`/api/tasks`、调度模块）。
- `✅ 已实现` GPU 资源管理与心跳上报（`/api/gpus`）。
- `✅ 已实现` RBAC 用户/角色/权限字典接口（`/api/users`、`/api/roles`、`/api/rbac`）。
- `✅ 已实现` 运维控制与监控接口（`/api/ops`、`/api/health`、`/api/metrics`）。
- `✅ 已实现` 实时推送能力（WebSocket STOMP，`/ws`）。

## 技术架构

### 技术栈
- Java 17
- Spring Boot 3.5.x
- Spring Security
- MyBatis-Plus
- MySQL
- Redis（含限流/队列相关使用）
- WebSocket(STOMP)
- springdoc-openapi（Swagger）
- Actuator + Prometheus

### 分层结构
1. 接入层：`controller` + `security`（HTTP 入口、鉴权、限流、幂等）。
2. 业务层：`service`（业务流程编排、规则处理）。
3. 调度层：`scheduler`（优先级队列、分配、状态机、执行模拟）。
4. 数据层：`mapper` + `entity` + MySQL/Redis。
5. 可观测层：`MonitoringController` + Actuator + WebSocket 推送。

## 核心数据流说明

### 1. 认证与访问控制数据流
1. 客户端调用 `/api/auth/login` 获取访问令牌。
2. 后续请求携带 `Authorization: Bearer <token>`。
3. `JwtAuthenticationFilter` 解析并注入用户身份与权限。
4. 控制器上的 `@PreAuthorize` 执行“角色/权限码”校验。
5. 失败时由统一响应结构返回错误（含 `errorCode`）。

状态：`✅ 已实现`

### 2. 任务提交到执行完成数据流
1. 客户端调用 `/api/tasks/submit` 提交任务。
2. 任务进入任务状态流转并写入队列。
3. `TaskDispatcher` 协同 `TaskPriorityQueue` 进行调度。
4. `GpuAllocator` 选择可用 GPU 资源。
5. `TaskExecutionSimulator` 执行模拟，`TaskCompletionMonitor` 回收结果并更新状态。
6. 状态变化通过通知模块推送到客户端。

状态：`✅ 已实现`

### 3. 监控与图表数据流
1. 客户端调用 `/api/health`、`/api/metrics` 获取运行指标。
2. 服务层聚合任务/GPU/系统健康数据。
3. 数据可用于前端 ECharts 图表渲染。
4. 遥测可通过 `/ws` 进行周期推送。

状态：`✅ 已实现`

## 当前实现边界
- `✅ 已实现` 调度与执行链路已完整打通（基于当前工程实现）。
- `✅ 已确认` 当前阶段不接入真实执行器，保持 `TaskExecutionSimulator` 线程模拟执行。
- `✅ 已保留冗余` 执行链路保留可切换扩展位，后续可按配置逐步演进到真实执行器。
