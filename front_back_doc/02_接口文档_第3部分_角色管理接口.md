# 接口文档（第3部分）：角色管理接口

## 1. 文档范围
- 控制器：`RoleController`
- 路径前缀：`/api/roles`
- 覆盖接口：角色 CRUD、角色-权限绑定、角色-用户绑定

## 2. 访问控制与通用约定

### 2.1 权限要求
- 控制器级鉴权：`hasAnyAuthority('ROLE_ADMIN','role:manage')`
- 未认证：`401`
- 无权限：`403`

### 2.2 统一响应结构（Result）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| code | Integer | 业务状态码 | 否 | 成功时 `200` |
| errorCode | String | 业务错误码 | 是 | `null` |
| message | String | 响应消息 | 否 | 成功时通常为`操作成功` |
| data | Object | 业务数据 | 是 | `null` |

### 2.3 常见错误码

| HTTP | errorCode | 场景 |
|---|---|---|
| 400 | `null` | 参数校验失败 |
| 400 | `ROLE_IN_USE` | 删除角色时仍存在用户绑定 |
| 401 | `AUTH_UNAUTHORIZED` | 未登录访问受保护资源 |
| 403 | `null` | 权限不足 |
| 404 | `RESOURCE_NOT_FOUND` | 角色/权限不存在 |
| 409 | `DUPLICATE_RESOURCE` | 角色编码冲突 |

## 3. 接口明细

---

### 3.1 创建角色
- **方法**：`POST`
- **路径**：`/api/roles`
- **鉴权**：是

#### 请求体（CreateRoleRequest）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| code | String | 角色编码 | 否 | 无 | `@NotBlank`, 最大50 |
| name | String | 角色名称 | 否 | 无 | `@NotBlank`, 最大100 |
| description | String | 角色描述 | 是 | `null` | - |
| roleType | Integer | 角色类型 | 是 | `1` | `1=System,2=Custom,3=Temporary` |
| status | Integer | 状态 | 是 | `1` | `0=禁用,1=启用` |
| sortOrder | Integer | 排序值 | 是 | `0` | 整数 |
| parentRoleId | Long | 父角色ID | 是 | `null` | 正整数 |
| permissionIds | List<Long> | 初始化权限ID集合 | 是 | `null` | 可为空数组 |

#### 成功响应 `data`（RoleResponse）

| 字段 | 类型 | 含义 | 可空 |
|---|---|---|---|
| id | Long | 角色ID | 否 |
| code | String | 角色编码 | 否 |
| name | String | 角色名称 | 否 |
| description | String | 角色描述 | 是 |
| roleType | Integer | 角色类型 | 是 |
| status | Integer | 状态 | 是 |
| sortOrder | Integer | 排序值 | 是 |
| parentRoleId | Long | 父角色ID | 是 |
| permissionIds | List<Long> | 权限ID列表 | 否 |
| createdAt | LocalDateTime | 创建时间 | 否 |
| updatedAt | LocalDateTime | 更新时间 | 否 |

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "id": 3,
    "code": "TASK_REVIEWER",
    "name": "任务审核员",
    "description": "审批高优任务",
    "roleType": 1,
    "status": 1,
    "sortOrder": 0,
    "parentRoleId": null,
    "permissionIds": [101, 102],
    "createdAt": "2026-04-03T11:00:00",
    "updatedAt": "2026-04-03T11:00:00"
  }
}
```

#### 失败示例（角色编码已存在）
```json
{
  "code": 409,
  "errorCode": "DUPLICATE_RESOURCE",
  "message": "角色编码已存在",
  "data": null
}
```

### 3.2 更新角色
- **方法**：`PUT`
- **路径**：`/api/roles/{roleId}`
- **鉴权**：是

#### 路径参数

| 字段 | 类型 | 含义 | 可空 |
|---|---|---|---|
| roleId | Long | 角色ID | 否 |

#### 请求体（UpdateRoleRequest）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 约束 |
|---|---|---|---|---|---|
| name | String | 角色名称 | 是 | `null` | 最大100 |
| description | String | 角色描述 | 是 | `null` | - |
| roleType | Integer | 角色类型 | 是 | `null` | `1=System,2=Custom,3=Temporary` |
| status | Integer | 状态 | 是 | `null` | - |
| sortOrder | Integer | 排序值 | 是 | `null` | - |
| parentRoleId | Long | 父角色ID | 是 | `null` | - |
| permissionIds | List<Long> | 角色权限列表 | 是 | `null` | `null=不改权限；[] = 清空权限` |

#### 行为说明
- 仅更新传入字段。
- `permissionIds != null` 时触发“先清空后重建”权限关系。

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "id": 3,
    "code": "TASK_REVIEWER",
    "name": "任务审批员",
    "description": "审批与拒绝高优先级任务",
    "roleType": 1,
    "status": 1,
    "sortOrder": 10,
    "parentRoleId": null,
    "permissionIds": [101, 103],
    "createdAt": "2026-04-03T11:00:00",
    "updatedAt": "2026-04-03T11:30:00"
  }
}
```

### 3.6 为角色分配权限
- **方法**：`POST`
- **路径**：`/api/roles/{roleId}/permissions`
- **鉴权**：是

#### 请求体（AssignPermissionsRequest）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 约束 |
|---|---|---|---|---|---|
| roleId | Long | 角色ID | 否 | 无 | `@NotNull`（应与路径一致） |
| permissionIds | List<Long> | 权限ID集合 | 否 | 无 | `@NotEmpty` |

#### 行为说明
- 服务层会先删除该角色现有权限，再写入 `permissionIds`。

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": null
}
```

#### 失败示例（权限不存在）
```json
{
  "code": 404,
  "errorCode": "RESOURCE_NOT_FOUND",
  "message": "权限不存在: 999",
  "data": null
}
```

---

### 3.7 撤销角色权限
- **方法**：`DELETE`
- **路径**：`/api/roles/{roleId}/permissions`
- **鉴权**：是

#### 请求体
- 与 `3.6 AssignPermissionsRequest` 相同。

#### 行为说明
- 仅删除请求中给出的权限ID，不影响未列出的权限。

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": null
}
```

---

### 3.8 为角色分配用户
- **方法**：`POST`
- **路径**：`/api/roles/{roleId}/users`
- **鉴权**：是

#### 请求体（AssignUsersRequest）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 约束 |
|---|---|---|---|---|---|
| roleId | Long | 角色ID | 否 | 无 | `@NotNull`（应与路径一致） |
| userIds | List<Long> | 用户ID集合 | 否 | 无 | `@NotEmpty` |
| expiresAt | LocalDateTime | 绑定过期时间 | 是 | `null` | - |

#### 行为说明
- 为 `userIds` 批量新增 `user_role` 关系，不先清空既有关联。

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": null
}
```

---

### 3.9 解除角色用户绑定
- **方法**：`DELETE`
- **路径**：`/api/roles/{roleId}/users`
- **鉴权**：是

#### 请求体
- 与 `3.8 AssignUsersRequest` 相同（`expiresAt`字段可忽略）。

#### 行为说明
- 遍历 `userIds` 删除 `(userId, roleId)` 绑定记录。

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": null
}
```

## 4. 联调注意事项
- `AssignPermissionsRequest.roleId`、`AssignUsersRequest.roleId` 与路径 `roleId` 存在重复：当前代码未做一致性校验，建议前端保持一致传值。
- 时间字段（`createdAt/updatedAt/expiresAt`）序列化格式：`yyyy-MM-dd HH:mm:ss`（时区：`Asia/Shanghai`）。
- 创建与更新中的 `permissionIds` 语义不同于“增量追加”，属于覆盖式设置。
