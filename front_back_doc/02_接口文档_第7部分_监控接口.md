# 接口文档（第7部分）：监控接口

## 1. 文档范围
- 控制器：`MonitoringController`
- 路径前缀：`/api`
- 覆盖接口：`GET /health`、`GET /metrics`

## 2. 访问控制与通用约定

### 2.1 权限要求
- 两个接口均要求：`hasAnyAuthority('ROLE_ADMIN','monitoring:read')`
- 未认证：`401`
- 无权限：`403`

### 2.2 统一响应结构（Result）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| code | Integer | 业务状态码 | 否 | 成功时 `200` |
| errorCode | String | 业务错误码 | 是 | `null` |
| message | String | 响应消息 | 否 | 成功时通常为`操作成功` |
| data | Object | 业务数据 | 是 | `null` |

## 3. 接口明细

---

### 3.1 获取系统健康状态
- **方法**：`GET`
- **路径**：`/api/health`
- **权限**：`ROLE_ADMIN` 或 `monitoring:read`

#### 成功响应 `data`（SystemHealth）

| 字段 | 类型 | 含义 | 取值示例 |
|---|---|---|---|
| status | String | 系统总体状态 | `UP` / `DEGRADED` / `DOWN` |
| dbStatus | String | MySQL 健康状态 | `UP` / `DOWN` |
| redisStatus | String | Redis 健康状态 | `UP` / `DOWN` |
| schedulerStatus | String | 调度器状态 | 当前固定 `UP` |
| circuitBreakerState | String | 熔断器状态 | `CLOSED` / `OPEN` / `HALF_OPEN` |
| oldestQueuedTaskSeconds | long | 队列最老任务等待秒数 | `-1` 表示队列为空 |

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "status": "UP",
    "dbStatus": "UP",
    "redisStatus": "UP",
    "schedulerStatus": "UP",
    "circuitBreakerState": "CLOSED",
    "oldestQueuedTaskSeconds": 45
  }
}
```

---

### 3.2 获取聚合指标
- **方法**：`GET`
- **路径**：`/api/metrics`
- **权限**：`ROLE_ADMIN` 或 `monitoring:read`

#### 成功响应 `data`（MetricsResponse）
- 结构：
- `tasks`: `TaskMetrics`
- `gpus`: `GpuMetrics`

### 3.2.1 tasks（TaskMetrics）字段

| 字段 | 类型 | 含义 |
|---|---|---|
| queueLength | long | 队列总长度 |
| queueLengthByPriority | Map<String,Long> | 队列分优先级长度 |
| taskCountByStatus | Map<String,Long> | 各状态任务数 |
| avgWaitSecondsByPriority | Map<String,Double> | 分优先级平均等待秒数 |
| avgDispatchLatencySeconds | Double | 平均派发时延（入队到运行） |
| avgTurnaroundSeconds | Double | 平均周转时延（入队到完成） |
| dispatchLatencyPercentilesSeconds | Map<String,Double> | 派发时延分位数（p50/p95/p99） |
| queueAgeHistogram | Map<String,Long> | 排队时长分桶（lt_1m/m1_5/m5_15/gte_15m） |
| completionRate | String | 完成率百分比字符串 |
| failureRate | String | 失败率百分比字符串 |
| failureReasons | Map<String,Long> | 失败原因分布 |
| allocationFailureReasons | Map<String,Long> | 分配失败原因分布 |
| userSlaCompliancePct | Map<Long,Double> | 用户SLA达标率 |
| retryQueueSize | Long | 重试队列长度 |
| dlqSize | Long | 死信队列长度 |
| pendingApprovalCount | Long | 待审批任务数 |
| webhookRetryQueueSize | Long | webhook重试队列长度 |

### 3.2.2 gpus（GpuMetrics）字段

| 字段 | 类型 | 含义 |
|---|---|---|
| total | long | GPU总数 |
| countByStatus | Map<String,Long> | 各状态GPU数 |
| utilizationRate | String | GPU利用率（百分比字符串） |
| usedMemoryGbByGpu | Map<Long,BigDecimal> | 各GPU已用显存GB |
| remainingMemoryGbByGpu | Map<Long,BigDecimal> | 各GPU剩余显存GB |
| vramFragmentationByGpu | Map<Long,BigDecimal> | 忙碌GPU显存碎片率（0-1） |
| idleSecondsByGpu | Map<Long,Long> | 空闲GPU空闲时长秒数 |

## 4. 与前端图表联调说明
- `/api/metrics` 适合作为大盘主数据源（任务 + GPU 一次返回）。
- 多个百分比字段为字符串（如 `25.0%`），ECharts 计算前需转数值。
- Map 键名（如 `High(8-10)`、`lt_1m`）可直接用作 X 轴分类。

## 5. 注意事项
- 与 GPU 管理接口中的 `/api/gpus/metrics` 不同：
- `/api/metrics` 返回复合监控结构（`tasks + gpus`）
- `/api/gpus/metrics` 返回简化 GPU 利用率摘要
