# 业务流程文档（第3部分）：认证与权限流程

## 1. 文档目标
- 说明从登录到接口访问鉴权的完整流程。
- 对齐“前端携带 Token 的调用行为”与“后端过滤链/权限判断”的实际实现。

## 2. 涉及模块
- 认证接口：`AuthController`
- 认证服务：`AuthService`
- 安全配置：`SecurityConfig`
- 鉴权过滤：`JwtAuthenticationFilter`、`RateLimitFilter`、`IdempotencyFilter`
- 用户加载：`CustomUserDetailsService`、`CustomUserDetails`
- 令牌工具/黑名单：`JwtUtil`、`TokenBlacklistService`

## 3. 认证主流程

### 3.1 登录流程
1. 前端调用 `POST /api/auth/login`，提交用户名密码。
2. `AuthService.login` 通过 `AuthenticationManager` 校验账号。
3. 校验成功后：
- 加载用户ID、用户名、角色码
- 生成 `accessToken` 与 `refreshToken`
- 返回 `LoginResponse`
4. 前端保存 token，后续请求携带 `Authorization: Bearer <accessToken>`。

### 3.2 刷新令牌流程
1. 前端调用 `POST /api/auth/refresh` 传 `refreshToken`。
2. `AuthService.refreshToken` 校验：
- token 合法性
- token 类型必须为 refresh
- 不在黑名单
- 用户存在且状态可用
3. 刷新成功后：
- 将旧 refresh token 拉黑
- 撤销该用户在某时刻前签发的 access token
- 签发新 token 对

### 3.3 登出流程
1. 前端调用 `POST /api/auth/logout`，可带 accessToken（Header）和 refreshToken（Body）。
2. `AuthService.logout` 至少要求一个可用令牌。
3. 有效令牌会被加入黑名单；并触发 access token 撤销截断。
4. 清理 `SecurityContext`，返回登出成功。

## 4. 接口访问鉴权流程

### 4.1 过滤链顺序（实际配置）
1. `IdempotencyFilter`
2. `RateLimitFilter`
3. `JwtAuthenticationFilter`
4. `UsernamePasswordAuthenticationFilter`（Spring 默认）

### 4.2 路由放行策略
- `permitAll`：`/api/auth/**`、`/api/public/**`、Swagger、`/actuator/health`、`/ws/**` 等。
- 其余接口：`authenticated()`。

### 4.3 JWT 解析与上下文注入
1. `JwtAuthenticationFilter` 从 `Authorization` 头提取 token。
2. token 合法且类型为 access 时继续；否则返回 `AUTH_TOKEN_TYPE_INVALID`。
3. 判断 token 是否在黑名单，或是否被 refresh 撤销截断。
4. 根据 userId 从 DB 重载用户信息与角色/权限。
5. 注入 `SecurityContext`，供后续 `@PreAuthorize` 使用。

## 5. RBAC 权限判断流程

### 5.1 Authority 组装
1. `CustomUserDetailsService` 加载用户角色列表。
2. 同时加载用户权限码列表（`permission.code`）。
3. `CustomUserDetails` 合并为 `GrantedAuthority` 集合：
- 角色码（如 `ROLE_ADMIN`）
- 权限码（如 `task:approval:review`）

### 5.2 访问控制执行点
- 控制器方法上使用 `@PreAuthorize("hasAnyAuthority(...)")`。
- 当前仓库已采用“角色或权限码”并行鉴权策略。

## 6. 安全防护分支

### 6.1 限流
- `RateLimitFilter` 对登录和普通 API 使用不同桶策略。
- 超限返回 `RATE_LIMIT_EXCEEDED`。
- 认证接口在 Redis 不可用时可按 `fail-closed` 返回 `AUTH_RATE_LIMIT_BACKEND_UNAVAILABLE`。

### 6.2 幂等
- `IdempotencyFilter` 对 `POST/PUT/DELETE` 支持 `X-Request-Id` 幂等。
- 同一请求号但指纹不一致时返回 `IDEMPOTENCY_CONFLICT`。

### 6.3 未授权入口
- `JwtAuthenticationEntryPoint` 统一返回 `401 + AUTH_UNAUTHORIZED`。

## 7. 页面与接口关系
- 登录页：`POST /api/auth/login`
- 刷新机制：`POST /api/auth/refresh`
- 当前用户信息：`GET /api/auth/me`
- 退出登录：`POST /api/auth/logout`
- 业务页面访问：携带 access token 调用各业务接口；前端按 `errorCode` 分流处理。

## 8. 错误处理建议（前端）
- `AUTH_UNAUTHORIZED`：跳转登录页。
- `AUTH_TOKEN_TYPE_INVALID` / `INVALID_TOKEN`：清理本地 token，触发重新登录。
- `RATE_LIMIT_EXCEEDED`：展示频控提示并按 `Retry-After` 重试。
- `IDEMPOTENCY_CONFLICT`：提示请求重复且参数不一致。

## 9. 风险与边界
- `/api/auth/**` 被全局放行，但其中 `logout/me` 在业务层仍依赖 token 校验。
- token 签发时写入角色码；权限码从数据库实时加载进 `SecurityContext`。
- CORS 允许来源模式为 `*`（不带凭据），前端应走 Bearer Token 模式。
