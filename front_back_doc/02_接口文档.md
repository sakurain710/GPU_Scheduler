## 认证接口


## 1. 文档范围
- 控制器：`AuthController`
- 路径前缀：`/api/auth`
- 覆盖接口：`/login`、`/refresh`、`/logout`、`/me`
- 本文只描述已在代码中实现的行为。

## 2. 通用约定

### 2.1 统一响应结构（Result）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| code | Integer | 业务状态码 | 否 | 成功时 `200` |
| errorCode | String | 业务错误码（用于前端分支处理） | 是 | `null` |
| message | String | 响应消息 | 否 | 成功时通常为`操作成功` |
| data | Object | 业务数据 | 是 | `null` |

### 2.2 公共请求头

| Header | 说明 | 必填 |
|---|---|---|
| Content-Type: application/json | JSON 请求体 | `POST` 接口是 |
| Authorization: Bearer <token> | 访问令牌 | `/logout`、`/me` 实际需要 |
| X-Request-Id | 幂等键（防重复提交） | 否（建议 `POST` 提供） |

### 2.3 认证相关错误码（本部分可能出现）

| HTTP | errorCode | 触发场景 |
|---|---|---|
| 400 | `null` | 请求参数校验失败（如字段为空） |
| 401 | `AUTH_UNAUTHORIZED` | 进入认证入口点时未授权 |
| 401 | `INVALID_TOKEN` | token 无效/类型错误/缺失等业务校验失败 |
| 429 | `RATE_LIMIT_EXCEEDED` | 限流触发 |
| 503 | `AUTH_RATE_LIMIT_BACKEND_UNAVAILABLE` | 认证接口限流后端不可用（fail-closed） |

## 3. 接口明细

---

### 3.1 用户登录
- **方法**：`POST`
- **路径**：`/api/auth/login`
- **鉴权**：否

#### 请求体

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| username | String | 用户名 | 否 | 无 | `@NotBlank` |
| password | String | 密码 | 否 | 无 | `@NotBlank` |

#### 成功响应 `data`（LoginResponse）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| accessToken | String | 访问令牌 | 否 | 无 | JWT |
| refreshToken | String | 刷新令牌 | 否 | 无 | JWT |
| tokenType | String | 令牌类型 | 否 | `Bearer` | 固定值 `Bearer` |
| expiresIn | Long | accessToken 有效秒数 | 否 | `86400` | 正整数 |
| userId | Long | 用户ID | 否 | 无 | 正整数 |
| username | String | 用户名 | 否 | 无 | - |
| roles | List<String> | 角色编码列表 | 否 | `[]` | 例如 `ROLE_ADMIN` |

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "accessToken": "<ACCESS_TOKEN>",
    "refreshToken": "<REFRESH_TOKEN>",
    "tokenType": "Bearer",
    "expiresIn": 86400,
    "userId": 1,
    "username": "alice",
    "roles": ["ROLE_ADMIN"]
  }
}
```

#### 失败示例（账号密码错误）
```json
{
  "code": 401,
  "errorCode": null,
  "message": "用户名或密码错误",
  "data": null
}
```

### 3.3 用户登出
- **方法**：`POST`
- **路径**：`/api/auth/logout`
- **鉴权**：路径级 `permitAll`，但业务上需要 `accessToken` 或 `refreshToken` 至少一个

#### 请求头
- 推荐提供：`Authorization: Bearer <accessToken>`

#### 请求体（可选）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| refreshToken | String | 可选刷新令牌（提供则一并拉黑） | 是 | `null` | JWT |

#### 成功响应
- `data` 固定为 `null`。

```json
{
  "code": 200,
  "errorCode": null,
  "message": "登出成功",
  "data": null
}
```

#### 失败示例（未提供任何可用令牌）
```json
{
  "code": 401,
  "errorCode": "INVALID_TOKEN",
  "message": "缺少登出令牌",
  "data": null
}
```

### 3.4 获取当前用户
- **方法**：`GET`
- **路径**：`/api/auth/me`
- **鉴权**：路径级 `permitAll`，但业务上需要有效 `accessToken`

#### 请求头
- 必填：`Authorization: Bearer <accessToken>`

#### 成功响应 `data`（UserResponse）

| 字段 | 类型 | 含义 | 可空 | 默认值 | 枚举/约束 |
|---|---|---|---|---|---|
| id | Long | 用户ID | 否 | 无 | 正整数 |
| username | String | 用户名 | 否 | 无 | - |
| email | String | 邮箱 | 是 | `null` | 邮箱格式由写入端保证 |
| status | Integer | 账号状态 | 否 | 无 | `1`启用；其他值为非启用状态 |
| roles | List<String> | 角色编码列表 | 否 | `[]` | 例如 `ROLE_ADMIN` |
| createdAt | LocalDateTime | 创建时间 | 否 | 无 | `yyyy-MM-dd HH:mm:ss`（Asia/Shanghai） |
| updatedAt | LocalDateTime | 更新时间 | 否 | 无 | `yyyy-MM-dd HH:mm:ss`（Asia/Shanghai） |

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {
    "id": 1,
    "username": "alice",
    "email": "alice@example.com",
    "status": 1,
    "roles": ["ROLE_ADMIN"],
    "createdAt": "2026-03-31T10:20:30",
    "updatedAt": "2026-04-03T09:00:00"
  }
}
```

#### 失败示例（未登录）
```json
{
  "code": 401,
  "errorCode": "INVALID_TOKEN",
  "message": "用户未登录",
  "data": null
}
```

## 4. 与前端联调注意事项
- `POST` 请求建议携带 `X-Request-Id`，避免重复提交导致语义不一致。
- 前端错误处理应优先判断 `errorCode`，其次再看 `message`。
- `/api/auth/me` 与 `/api/auth/logout` 虽位于 `permitAll` 前缀下，但实际需要 token 才能得到业务成功响应。

## 用户管理接口


## 1. 文档范围
- 控制器：`UserController`
- 路径前缀：`/api/users`
- 覆盖接口：创建、更新、删除、详情、分页列表、分配角色

## 2. 访问控制与通用约定

### 2.1 权限要求
- 控制器级鉴权：`hasAnyAuthority('ROLE_ADMIN','user:manage')`
- 未认证：返回 `401`
- 无权限：返回 `403`

### 2.2 统一响应结构（Result）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| code | Integer | 业务状态码 | 否 | 成功时 `200` |
| errorCode | String | 业务错误码 | 是 | `null` |
| message | String | 响应消息 | 否 | 成功时通常为`操作成功` |
| data | Object | 业务数据 | 是 | `null` |

### 2.3 常见错误码

| HTTP | errorCode | 场景 |
|---|---|---|
| 400 | `null` | 参数校验失败（如邮箱格式错误） |
| 401 | `AUTH_UNAUTHORIZED` | 未登录访问受保护资源 |
| 403 | `null` | 权限不足 |
| 404 | `RESOURCE_NOT_FOUND` | 用户/角色不存在 |
| 409 | `DUPLICATE_RESOURCE` | 用户名或邮箱冲突 |

### 3.6 为用户分配角色
- **方法**：`POST`
- **路径**：`/api/users/{userId}/roles`
- **鉴权**：是

#### 路径参数

| 字段 | 类型 | 含义 | 可空 |
|---|---|---|---|
| userId | Long | 用户ID | 否 |

#### 请求体
- 类型：`List<Long>`（角色ID数组）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| body | List<Long> | 角色ID集合 | 是 | `null` |

#### 查询参数

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| expiresAt | LocalDateTime | 角色过期时间 | 是 | `null` |

#### 行为说明
- 先清空该用户已有角色，再按 `roleIds` 重建绑定。
- `roleIds` 为空或不传时，结果为“清空角色”。
- 任一角色ID不存在时，返回 `404`。

#### 成功示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": null
}
```

#### 失败示例（角色不存在）
```json
{
  "code": 404,
  "errorCode": "RESOURCE_NOT_FOUND",
  "message": "角色不存在: 999",
  "data": null
}
```

## 4. 联调注意事项
- `assignRoles` 是覆盖写入语义，不是增量追加。
- 时间字段 `createdAt/updatedAt/expiresAt` 统一采用全局 Jackson 配置：`yyyy-MM-dd HH:mm:ss`（时区：`Asia/Shanghai`）。
- 列表接口排序字段超出允许集合时会回退到 `createdAt` 排序。

## 4. 与前端图表联调说明
- `/api/metrics` 适合作为大盘主数据源（任务 + GPU 一次返回）。
- 多个百分比字段为字符串（如 `25.0%`），ECharts 计算前需转数值。
- Map 键名（如 `High(8-10)`、`lt_1m`）可直接用作 X 轴分类。

## 5. 注意事项
- 与 GPU 管理接口中的 `/api/gpus/metrics` 不同：
- `/api/metrics` 返回复合监控结构（`tasks + gpus`）
- `/api/gpus/metrics` 返回简化 GPU 利用率摘要

## 运维接口


## 1. 文档范围
- 控制器：`OpsController`
- 路径前缀：`/api/ops`
- 覆盖接口：调度器控制、熔断器重置、DLQ 管理、强制任务操作、通知重试状态

## 2. 权限与通用约定

### 2.1 权限要求
- 控制器级鉴权：`hasAnyAuthority('ROLE_ADMIN','ops:manage')`
- 未认证：`401`
- 无权限：`403`

### 2.2 统一响应结构（Result）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| code | Integer | 业务状态码 | 否 | 成功时 `200` |
| errorCode | String | 业务错误码 | 是 | `null` |
| message | String | 响应消息 | 否 | 成功时通常为`操作成功` |
| data | Object | 业务数据 | 是 | `null` |

### 2.3 常见错误码

| HTTP | errorCode | 场景 |
|---|---|---|
| 400 | `INVALID_TASK_ID` | DLQ 重处理 taskId 非法 |
| 400 | `TASK_NOT_RUNNING` | 强制失败/抢占时任务不在 RUNNING |
| 401 | `AUTH_UNAUTHORIZED` | 未认证 |
| 403 | `null` | 权限不足 |
| 404 | `RESOURCE_NOT_FOUND` | DLQ中未找到任务 |
| 409 | `INVALID_TASK_STATE` | 强制重入队触发非法状态转换 |

### 3.7 重处理死信任务
- **方法**：`POST`
- **路径**：`/api/ops/dlq/{taskId}/reprocess`

#### 路径参数

| 字段 | 类型 | 含义 | 可空 |
|---|---|---|---|
| taskId | Long | 任务ID | 否 |

#### 行为说明
- 从 DLQ 中移除指定任务后，尝试将任务迁移到 `QUEUED`。
- 成功返回 `reprocessed=true`；未找到则 `404`。

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {"taskId": 123, "reprocessed": true}
}
```

#### 失败示例（不在DLQ）
```json
{
  "code": 404,
  "errorCode": "RESOURCE_NOT_FOUND",
  "message": "DLQ task not found: 123",
  "data": null
}
```

### 3.10 强制任务失败
- **方法**：`POST`
- **路径**：`/api/ops/tasks/{taskId}/force-fail`

#### 请求体（可选）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| reason | String | 失败原因 | 是 | `Forced failed by operator` |

#### 业务规则
- 仅 `RUNNING` 任务允许强制失败。
- 若提供 `reason`，写入任务 `errorMessage`。

#### 失败示例（非运行态）
```json
{
  "code": 400,
  "errorCode": "TASK_NOT_RUNNING",
  "message": "Only RUNNING task can be force-failed",
  "data": null
}
```

---

### 3.11 抢占运行任务并重入队
- **方法**：`POST`
- **路径**：`/api/ops/tasks/{taskId}/preempt`

#### 请求体（可选）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| reason | String | 抢占原因 | 是 | `Preempted by operator` |

#### 业务规则
- 仅 `RUNNING` 任务允许抢占。
- 成功后任务重入 `QUEUED`，返回 `preempted=true`。

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {"taskId": 123, "preempted": true}
}
```

## 4. 联调注意事项
- `force-requeue`、`force-fail`、`preempt` 均走状态机或运行态校验，前端应按 `errorCode` 分流提示。
- `dlq.clear` 的 `removed` 为“是否删除成功”标记，不是条目计数。
- `drainQueue`/`force-fail`/`preempt` 的 `reason` 为空时后端会填充默认值。
