# 前后端字段映射说明（第3部分：GPU与任务域）

## 1. 范围
- 后端来源：`GpuController`、`GpuTaskController`、`dto/gpu/*`、`dto/task/*`。
- 前端范围：GPU资源管理、任务提交与我的任务、任务审批操作。

## 2. 路径映射约定（推荐/兼容）

| 模块 | 推荐路径前缀 | 兼容路径前缀 | 说明 |
|---|---|---|---|
| GPU资源 | `/api/gpus` | `/api/gpu` | 控制器同时支持，前端统一使用推荐路径 |
| 任务管理 | `/api/tasks` | `/api/task` | 控制器同时支持，前端统一使用推荐路径 |

## 3. GPU 模块字段映射（`/api/gpus`）

### 3.1 GPU分页列表 `GET /api/gpus`
请求参数映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 默认值/约束 |
|---|---|---|---|---|
| `page` | `@RequestParam page` | number | 否 | 默认 `1`，最小 `1` |
| `size` | `@RequestParam size` | number | 否 | 默认 `20`，区间 `1-200` |
| `status` | `@RequestParam status` | number | 否 | `1=IDLE,2=BUSY,3=OFFLINE,4=MAINTENANCE` |
| `sortBy` | `@RequestParam sortBy` | string | 否 | 默认 `id`，可选 `id/name/memoryGb/computingPowerTflops/status/createdAt` |
| `sortDir` | `@RequestParam sortDir` | string | 否 | 默认 `asc`，可选 `asc/desc` |

响应 `data`（`IPage<GpuResponse>`）字段映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `records` | `IPage.records` | GpuResponse[] | 是 | 当前页GPU列表 |
| `total` | `IPage.total` | number | 是 | 总条数 |
| `size` | `IPage.size` | number | 是 | 每页大小 |
| `current` | `IPage.current` | number | 是 | 当前页 |
| `pages` | `IPage.pages` | number | 是 | 总页数 |

`GpuResponse` 映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | `GpuResponse.id` | number | 是 | GPU ID |
| `name` | `GpuResponse.name` | string | 是 | GPU型号名 |
| `manufacturer` | `GpuResponse.manufacturer` | string | 是 | 制造商 |
| `memoryGb` | `GpuResponse.memoryGb` | number | 是 | 显存(GB) |
| `computingPowerTflops` | `GpuResponse.computingPowerTflops` | number | 是 | 算力(TFLOPS) |
| `status` | `GpuResponse.status` | number | 是 | 状态码 `1/2/3/4` |
| `statusLabel` | `GpuResponse.statusLabel` | string | 否 | 状态文本 |
| `remark` | `GpuResponse.remark` | string | 否 | 备注 |
| `createdBy` | `GpuResponse.createdBy` | number | 否 | 创建人用户ID |
| `createdAt` | `GpuResponse.createdAt` | string | 否 | ISO-8601 |
| `updatedAt` | `GpuResponse.updatedAt` | string | 否 | ISO-8601 |

### 3.2 GPU详情 `GET /api/gpus/{gpuId}`

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `gpuId` | `@PathVariable gpuId` | number | 是 | GPU主键 |

响应 `data`：`GpuResponse`。

### 3.3 注册GPU `POST /api/gpus`
请求（`RegisterGpuRequest`）映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 校验/约束 |
|---|---|---|---|---|
| `name` | `RegisterGpuRequest.name` | string | 是 | `@NotBlank`，最大128 |
| `manufacturer` | `RegisterGpuRequest.manufacturer` | string | 是 | `@NotBlank`，最大64 |
| `memoryGb` | `RegisterGpuRequest.memoryGb` | number | 是 | `> 0` |
| `computingPowerTflops` | `RegisterGpuRequest.computingPowerTflops` | number | 是 | `> 0` |
| `remark` | `RegisterGpuRequest.remark` | string | 否 | 最大255 |

响应 `data`：`GpuResponse`。

### 3.4 更新GPU状态 `PUT /api/gpus/{gpuId}/status`

| 前端字段 | 后端字段 | 类型 | 必填 | 约束 |
|---|---|---|---|---|
| `gpuId` | `@PathVariable gpuId` | number | 是 | 目标GPU |
| `status` | `UpdateGpuStatusRequest.status` | number | 是 | `1-4` |

响应 `data`：`GpuResponse`。

### 3.5 删除GPU `DELETE /api/gpus/{gpuId}`

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `gpuId` | `@PathVariable gpuId` | number | 是 | 删除目标GPU |

响应 `data`：`null`。

### 3.6 GPU健康摘要 `GET /api/gpus/health`
响应 `data`：`Map<String, Long>`（键值由服务端定义，前端按 key/value 动态渲染）。

### 3.7 GPU利用率指标 `GET /api/gpus/metrics`
响应 `data`：`Map<String, Object>`（指标模型动态，前端需容错字段缺失）。

### 3.8 Worker心跳上报 `POST /api/gpus/{gpuId}/heartbeat`
响应 `data` 字段：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `gpuId` | `data.gpuId` | number | 是 | GPU ID |
| `accepted` | `data.accepted` | boolean | 是 | 是否接收 |
| `heartbeatAgeSeconds` | `data.heartbeatAgeSeconds` | number | 是 | 心跳年龄（秒） |

## 4. 任务模块字段映射（`/api/tasks`）

### 4.1 提交任务 `POST /api/tasks/submit`
请求（`SubmitTaskRequest`）映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 校验/示例 |
|---|---|---|---|---|
| `title` | `SubmitTaskRequest.title` | string | 是 | `@NotBlank`，最大128 |
| `description` | `SubmitTaskRequest.description` | string | 否 | 最大65535 |
| `taskType` | `SubmitTaskRequest.taskType` | string | 是 | `@NotBlank`，示例 `model_training` |
| `minMemoryGb` | `SubmitTaskRequest.minMemoryGb` | number | 是 | `> 0` |
| `computeUnitsGflop` | `SubmitTaskRequest.computeUnitsGflop` | number | 是 | `> 0` |
| `basePriority` | `SubmitTaskRequest.basePriority` | number | 否 | 默认 `5`，区间 `1-10` |

响应 `data`：`TaskResponse`（见 4.6）。

### 4.2 任务详情 `GET /api/tasks/{taskId}`

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `taskId` | `@PathVariable taskId` | number | 是 | 任务ID |

响应 `data`：`TaskResponse`。

### 4.3 我的任务列表 `GET /api/tasks/my`
请求参数映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 默认值/约束 |

| `size` | `@RequestParam size` | number | 否 | 默认 `10`，区间 `1-200` |

| `title` | `TaskResponse.title` | string | 是 | 标题 |
| `description` | `TaskResponse.description` | string | 否 | 描述 |

| `computeUnitsGflop` | `TaskResponse.computeUnitsGflop` | number | 是 | 计算量估值 |
| `basePriority` | `TaskResponse.basePriority` | number | 是 | 基础优先级 |
| `status` | `TaskResponse.status` | number | 是 | 状态码 |

## 5. 前端实现约定
- 前端只使用推荐路径（复数资源名），兼容路径仅保留历史适配。
- `GpuResponse.status` 与 `TaskResponse.status` 建议在前端统一维护枚举字典，`statusLabel` 仅用于兜底显示。
- `metrics/health` 响应为动态键值结构，前端应做 `key in data` 判断，避免字段强耦合。
