# 接口文档（第8部分）：运维接口

## 1. 文档范围
- 控制器：`OpsController`
- 路径前缀：`/api/ops`
- 覆盖接口：调度器控制、熔断器重置、DLQ 管理、强制任务操作、通知重试状态

## 2. 权限与通用约定

### 2.1 权限要求
- 控制器级鉴权：`hasAnyAuthority('ROLE_ADMIN','ops:manage')`
- 未认证：`401`
- 无权限：`403`

### 2.2 统一响应结构（Result）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| code | Integer | 业务状态码 | 否 | 成功时 `200` |
| errorCode | String | 业务错误码 | 是 | `null` |
| message | String | 响应消息 | 否 | 成功时通常为`操作成功` |
| data | Object | 业务数据 | 是 | `null` |

### 2.3 常见错误码

| HTTP | errorCode | 场景 |
|---|---|---|
| 400 | `INVALID_TASK_ID` | DLQ 重处理 taskId 非法 |
| 400 | `TASK_NOT_RUNNING` | 强制失败/抢占时任务不在 RUNNING |
| 401 | `AUTH_UNAUTHORIZED` | 未认证 |
| 403 | `null` | 权限不足 |
| 404 | `RESOURCE_NOT_FOUND` | DLQ中未找到任务 |
| 409 | `INVALID_TASK_STATE` | 强制重入队触发非法状态转换 |

## 3. 接口明细

---

### 3.1 暂停调度器
- **方法**：`POST`
- **路径**：`/api/ops/dispatcher/pause`

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {"paused": true}
}
```

---

### 3.2 恢复调度器
- **方法**：`POST`
- **路径**：`/api/ops/dispatcher/resume`

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {"paused": false}
}
```

---

### 3.3 查询调度器状态
- **方法**：`GET`
- **路径**：`/api/ops/dispatcher/status`

#### 成功响应

| 字段 | 类型 | 含义 |
|---|---|---|
| paused | Boolean | 当前调度暂停状态 |

---

### 3.4 重置熔断器
- **方法**：`POST`
- **路径**：`/api/ops/circuit-breaker/reset`

#### 成功响应

| 字段 | 类型 | 含义 |
|---|---|---|
| state | String | 熔断器状态名 |
| failureCount | Integer | 当前失败计数 |

#### 示例
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {"state": "CLOSED", "failureCount": 0}
}
```

---

### 3.5 查看死信队列（DLQ）
- **方法**：`GET`
- **路径**：`/api/ops/dlq`

#### 成功响应

| 字段 | 类型 | 含义 |
|---|---|---|
| size | Long | DLQ 当前长度 |
| items | List<String> | 死信条目 JSON 字符串列表（最多100条） |

#### 条目结构示例（字符串内容）
```json
{"taskId":123,"attempt":4,"reason":"No available GPU","time":"2026-04-03T14:00:00"}
```

---

### 3.6 清空死信队列
- **方法**：`POST`
- **路径**：`/api/ops/dlq/clear`

#### 成功响应

| 字段 | 类型 | 含义 |
|---|---|---|
| removed | Long | 删除结果标记（删除键成功=1，未删除=0） |

说明：`removed` 不是“删除条目数”。

---

### 3.7 重处理死信任务
- **方法**：`POST`
- **路径**：`/api/ops/dlq/{taskId}/reprocess`

#### 路径参数

| 字段 | 类型 | 含义 | 可空 |
|---|---|---|---|
| taskId | Long | 任务ID | 否 |

#### 行为说明
- 从 DLQ 中移除指定任务后，尝试将任务迁移到 `QUEUED`。
- 成功返回 `reprocessed=true`；未找到则 `404`。

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {"taskId": 123, "reprocessed": true}
}
```

#### 失败示例（不在DLQ）
```json
{
  "code": 404,
  "errorCode": "RESOURCE_NOT_FOUND",
  "message": "DLQ task not found: 123",
  "data": null
}
```

---

### 3.8 强制任务重入队
- **方法**：`POST`
- **路径**：`/api/ops/tasks/{taskId}/force-requeue`

#### 行为说明
- 直接调用状态迁移到 `QUEUED`。
- 受状态机约束，非法迁移返回 `INVALID_TASK_STATE`。

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": null
}
```

---

### 3.9 清空排队任务
- **方法**：`POST`
- **路径**：`/api/ops/queue/drain`

#### 请求体（可选，RejectTaskRequest）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| reason | String | 批量取消原因 | 是 | `Queue drained by operator` |

#### 成功响应

| 字段 | 类型 | 含义 |
|---|---|---|
| drained | Integer | 实际取消任务数 |
| reason | String | 本次使用的原因 |

---

### 3.10 强制任务失败
- **方法**：`POST`
- **路径**：`/api/ops/tasks/{taskId}/force-fail`

#### 请求体（可选）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| reason | String | 失败原因 | 是 | `Forced failed by operator` |

#### 业务规则
- 仅 `RUNNING` 任务允许强制失败。
- 若提供 `reason`，写入任务 `errorMessage`。

#### 失败示例（非运行态）
```json
{
  "code": 400,
  "errorCode": "TASK_NOT_RUNNING",
  "message": "Only RUNNING task can be force-failed",
  "data": null
}
```

---

### 3.11 抢占运行任务并重入队
- **方法**：`POST`
- **路径**：`/api/ops/tasks/{taskId}/preempt`

#### 请求体（可选）

| 字段 | 类型 | 含义 | 可空 | 默认值 |
|---|---|---|---|---|
| reason | String | 抢占原因 | 是 | `Preempted by operator` |

#### 业务规则
- 仅 `RUNNING` 任务允许抢占。
- 成功后任务重入 `QUEUED`，返回 `preempted=true`。

#### 成功响应
```json
{
  "code": 200,
  "errorCode": null,
  "message": "操作成功",
  "data": {"taskId": 123, "preempted": true}
}
```

---

### 3.12 查询通知重试队列状态
- **方法**：`GET`
- **路径**：`/api/ops/notification/webhook/retry/status`

#### 成功响应

| 字段 | 类型 | 含义 |
|---|---|---|
| queueSize | Long | webhook 重试队列长度 |

## 4. 联调注意事项
- `force-requeue`、`force-fail`、`preempt` 均走状态机或运行态校验，前端应按 `errorCode` 分流提示。
- `dlq.clear` 的 `removed` 为“是否删除成功”标记，不是条目计数。
- `drainQueue`/`force-fail`/`preempt` 的 `reason` 为空时后端会填充默认值。
