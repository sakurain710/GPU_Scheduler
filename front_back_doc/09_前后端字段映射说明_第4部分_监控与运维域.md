# 前后端字段映射说明（第4部分：监控与运维域）

## 1. 范围
- 后端来源：`MonitoringController`、`OpsController`、`dto/monitor/*`、`TaskStatusNotification`、`WebSocketConfig`。
- 前端范围：监控大盘、运维控制台、实时订阅消息处理。

## 2. 监控接口字段映射（`/api`）

### 2.1 系统健康 `GET /api/health`
响应 `data`（`SystemHealth`）映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `status` | `SystemHealth.status` | string | 是 | `UP / DEGRADED / DOWN` |
| `dbStatus` | `SystemHealth.dbStatus` | string | 是 | MySQL连通状态 |
| `redisStatus` | `SystemHealth.redisStatus` | string | 是 | Redis连通状态 |
| `schedulerStatus` | `SystemHealth.schedulerStatus` | string | 是 | 调度器状态 |
| `circuitBreakerState` | `SystemHealth.circuitBreakerState` | string | 是 | 熔断器状态 |
| `oldestQueuedTaskSeconds` | `SystemHealth.oldestQueuedTaskSeconds` | number | 是 | 队列最老任务等待秒数，`-1` 代表队列为空 |

### 2.2 合并指标 `GET /api/metrics`
响应 `data`（`MetricsResponse`）结构：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `tasks` | `MetricsResponse.tasks` | object | 是 | 任务指标对象（`TaskMetrics`） |
| `gpus` | `MetricsResponse.gpus` | object | 是 | GPU指标对象（`GpuMetrics`） |

`tasks`（`TaskMetrics`）映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `queueLength` | `TaskMetrics.queueLength` | number | 是 | 队列总长度 |
| `queueLengthByPriority` | `TaskMetrics.queueLengthByPriority` | Record<string, number> | 否 | 按优先级分桶 |
| `taskCountByStatus` | `TaskMetrics.taskCountByStatus` | Record<string, number> | 否 | 按状态统计 |
| `avgWaitSecondsByPriority` | `TaskMetrics.avgWaitSecondsByPriority` | Record<string, number> | 否 | 各优先级平均等待 |
| `avgDispatchLatencySeconds` | `TaskMetrics.avgDispatchLatencySeconds` | number | 否 | 平均调度延迟 |
| `avgTurnaroundSeconds` | `TaskMetrics.avgTurnaroundSeconds` | number | 否 | 平均周转时长 |
| `dispatchLatencyPercentilesSeconds` | `TaskMetrics.dispatchLatencyPercentilesSeconds` | Record<string, number> | 否 | 延迟分位值 |
| `queueAgeHistogram` | `TaskMetrics.queueAgeHistogram` | Record<string, number> | 否 | 队龄分布 |
| `completionRate` | `TaskMetrics.completionRate` | string | 否 | 完成率（字符串百分比） |
| `failureRate` | `TaskMetrics.failureRate` | string | 否 | 失败率（字符串百分比） |
| `failureReasons` | `TaskMetrics.failureReasons` | Record<string, number> | 否 | 失败原因分布 |
| `allocationFailureReasons` | `TaskMetrics.allocationFailureReasons` | Record<string, number> | 否 | 分配失败原因 |
| `userSlaCompliancePct` | `TaskMetrics.userSlaCompliancePct` | Record<string, number> | 否 | 用户SLA达标率 |
| `retryQueueSize` | `TaskMetrics.retryQueueSize` | number | 否 | 重试队列大小 |
| `dlqSize` | `TaskMetrics.dlqSize` | number | 否 | 死信队列大小 |
| `pendingApprovalCount` | `TaskMetrics.pendingApprovalCount` | number | 否 | 待审批任务数 |
| `webhookRetryQueueSize` | `TaskMetrics.webhookRetryQueueSize` | number | 否 | webhook重试队列大小 |

`gpus`（`GpuMetrics`）映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `total` | `GpuMetrics.total` | number | 是 | GPU总数 |
| `countByStatus` | `GpuMetrics.countByStatus` | Record<string, number> | 否 | 各状态GPU数量 |
| `utilizationRate` | `GpuMetrics.utilizationRate` | string | 否 | 整体利用率（字符串百分比） |
| `usedMemoryGbByGpu` | `GpuMetrics.usedMemoryGbByGpu` | Record<string, number> | 否 | 每卡已用显存 |
| `remainingMemoryGbByGpu` | `GpuMetrics.remainingMemoryGbByGpu` | Record<string, number> | 否 | 每卡剩余显存 |
| `vramFragmentationByGpu` | `GpuMetrics.vramFragmentationByGpu` | Record<string, number> | 否 | 显存碎片率 |
| `idleSecondsByGpu` | `GpuMetrics.idleSecondsByGpu` | Record<string, number> | 否 | 空闲时长秒数 |

## 3. 运维接口字段映射（`/api/ops`）

### 3.1 调度器控制

| 接口 | 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|---|
| `POST /dispatcher/pause` | `paused` | `data.paused` | boolean | 是 | 固定返回 `true` |
| `POST /dispatcher/resume` | `paused` | `data.paused` | boolean | 是 | 固定返回 `false` |
| `GET /dispatcher/status` | `paused` | `data.paused` | boolean | 是 | 当前调度暂停状态 |

### 3.2 熔断器与死信队列

`POST /circuit-breaker/reset` 响应：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `state` | `data.state` | string | 是 | 熔断器状态名 |
| `failureCount` | `data.failureCount` | number | 是 | 当前失败计数 |

`GET /dlq` 响应：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `size` | `data.size` | number | 是 | 死信队列数量 |
| `items` | `data.items` | array | 是 | 死信任务条目列表（动态结构） |

`POST /dlq/clear` 响应：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `removed` | `data.removed` | number | 是 | 清理条数 |

`POST /dlq/{taskId}/reprocess` 响应：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `taskId` | `data.taskId` | number | 是 | 重处理任务ID |
| `reprocessed` | `data.reprocessed` | boolean | 是 | 是否重处理成功 |

### 3.3 队列与任务强制操作

`POST /queue/drain` 请求体：`RejectTaskRequest.reason`（可选）。

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `reason` | `RejectTaskRequest.reason` | string | 否 | 排空队列原因 |

`POST /queue/drain` 响应：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `drained` | `data.drained` | number | 是 | 排空任务数 |
| `reason` | `data.reason` | string | 是 | 实际使用原因 |

`POST /tasks/{taskId}/preempt` 响应：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `taskId` | `data.taskId` | number | 是 | 被抢占任务ID |
| `preempted` | `data.preempted` | boolean | 是 | 固定 `true` |

`POST /tasks/{taskId}/force-requeue`、`POST /tasks/{taskId}/force-fail`：响应 `data` 均为 `null`。

### 3.4 通知重试队列状态
`GET /notification/webhook/retry/status` 响应：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `queueSize` | `data.queueSize` | number | 是 | webhook重试队列长度 |

## 4. 实时消息字段映射（WebSocket/STOMP）

### 4.1 连接与订阅

| 前端概念 | 后端配置 | 说明 |
|---|---|---|
| SockJS连接端点 | `/ws` | `WebSocketConfig.registerStompEndpoints` |
| 消息代理前缀 | `/topic`、`/queue` | `WebSocketConfig.configureMessageBroker` |
| 遥测主题 | `/topic/telemetry` | 默认值，可通过 `telemetry.topic` 配置覆盖 |
| 任务状态主题 | `/topic/task-status/{userId}` | `notification.task-topic-prefix` + `userId` |

### 4.2 遥测消息体（`TelemetrySnapshot`）

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `timestamp` | `TelemetrySnapshot.timestamp` | string | 是 | 快照时间 |
| `health` | `TelemetrySnapshot.health` | object | 是 | `SystemHealth` |
| `tasks` | `TelemetrySnapshot.tasks` | object | 是 | `TaskMetrics` |
| `gpus` | `TelemetrySnapshot.gpus` | object | 是 | `GpuMetrics` |

### 4.3 任务状态消息体（`TaskStatusNotification`）

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `taskId` | `TaskStatusNotification.taskId` | number | 是 | 任务ID |
| `userId` | `TaskStatusNotification.userId` | number | 是 | 归属用户ID |
| `fromStatus` | `TaskStatusNotification.fromStatus` | string | 否 | 旧状态文本 |
| `toStatus` | `TaskStatusNotification.toStatus` | string | 是 | 新状态文本 |
| `occurredAt` | `TaskStatusNotification.occurredAt` | string | 是 | 发生时间 |
| `message` | `TaskStatusNotification.message` | string | 否 | 错误/拒绝原因 |

## 5. 前端实现约定
- 监控接口与运维接口均走统一响应壳，先判 `code`，再按 `errorCode` 做异常分流。
- 监控指标中 `Map` 类型字段建议按“动态 key-value”渲染，不要写死完整键名集合。
- STOMP订阅建议在登录成功后以 `userId` 拼接个人任务主题，并在登出时主动取消订阅。
