# 页面功能结构与交互说明（第2部分）：任务中心与审批

## 1. 文档范围
- 本部分覆盖页面模块：
1. 任务提交页
2. 我的任务列表页
3. 任务详情页
4. 审批中心页（待审批任务）
- 仅描述功能结构与交互，不包含视觉设计。

## 2. 页面模块一：任务提交页（Task Submit）

### 2.1 页面结构（功能区域）
- 基础信息区：`title`、`description`、`taskType`
- 资源需求区：`minMemoryGb`、`computeUnitsGflop`
- 调度参数区：`basePriority`
- 提交动作区：提交按钮、重置按钮
- 反馈区：提交结果与错误提示

### 2.2 展示数据来源
- 前端表单状态
- 提交响应：`TaskResponse`

### 2.3 操作行为
1. 用户填写任务并提交。
2. 调用 `POST /api/tasks/submit`（兼容 `/api/task/submit`）。
3. 根据响应状态进入两类结果：
- 普通任务：进入 `QUEUED`
- 高优任务且无审批权限：进入 `PENDING_APPROVAL`
4. 成功后跳转“我的任务”或进入任务详情。

### 2.4 状态变化
- `editing` -> `submitting` -> `submitted`
- `editing` -> `submitting` -> `submit_failed`

### 2.5 接口依赖
- `POST /api/tasks/submit`
- 典型错误：`TASK_ACTIVE_LIMIT_EXCEEDED`、参数校验失败、限流错误

## 3. 页面模块二：我的任务列表页（My Tasks）

### 3.1 页面结构（功能区域）
- 过滤区：状态筛选、排序字段、排序方向
- 列表区：任务表格（状态、优先级、显存需求、创建时间等）
- 分页区：页码/每页大小
- 行操作区：查看详情、取消任务（按状态可见）

### 3.2 展示数据来源
- `GET /api/tasks/my` 返回 `IPage<TaskResponse>`

### 3.3 操作行为
1. 页面加载拉取当前用户任务分页。
2. 用户调整过滤条件后重新查询。
3. 点击某行进入详情页。
4. 对可取消任务执行取消操作。

### 3.4 状态变化
- `loading` -> `loaded`
- `loaded` -> `filtering` -> `loaded`
- `loaded` -> `cancelling` -> `cancelled`

### 3.5 接口依赖
- `GET /api/tasks/my?page&size&status&sortBy&sortDir`
- `POST /api/tasks/{taskId}/cancel`

## 4. 页面模块三：任务详情页（Task Detail）

### 4.1 页面结构（功能区域）
- 基础信息区：标题、类型、提交人
- 资源与调度区：优先级、显存需求、计算量、GPU绑定
- 执行进度区：状态、估算耗时、实际耗时、关键时间点
- 异常信息区：`errorMessage`
- 操作区：取消任务（权限与状态满足时）

### 4.2 展示数据来源
- `GET /api/tasks/{taskId}` 的 `TaskResponse`
- （可选）用户专属状态推送：`/topic/task-status/{userId}`

### 4.3 操作行为
1. 路由进入后拉取详情。
2. 若任务状态变化，刷新或实时更新页面状态。
3. 用户可在允许状态下取消任务。

### 4.4 状态变化
- `detail_loading` -> `detail_ready`
- `detail_ready` -> `status_updating` -> `detail_ready`

### 4.5 接口依赖
- `GET /api/tasks/{taskId}`
- `POST /api/tasks/{taskId}/cancel`

## 5. 页面模块四：审批中心页（Approval Center）

### 5.1 页面结构（功能区域）
- 筛选分页区：页码、每页大小、排序
- 待审批列表区：`PENDING_APPROVAL` 任务列表
- 审批动作区：通过、拒绝（拒绝原因输入）
- 处理反馈区：操作结果提示

### 5.2 展示数据来源
- `GET /api/tasks/approval/pending` 返回 `IPage<TaskResponse>`

### 5.3 操作行为
1. 审批人打开页面加载待审批任务。
2. 点击“通过”调用审批通过接口。
3. 点击“拒绝”填写原因并提交。
4. 操作成功后刷新列表并同步状态统计。

### 5.4 状态变化
- `pending_loading` -> `pending_ready`
- `pending_ready` -> `approving` -> `approved`
- `pending_ready` -> `rejecting` -> `rejected`

### 5.5 接口依赖
- `GET /api/tasks/approval/pending`
- `POST /api/tasks/{taskId}/approve`
- `POST /api/tasks/{taskId}/reject`
- 权限要求：`ROLE_ADMIN/ROLE_TASK_REVIEWER/task:approval:*`

## 6. 跨页面交互规则（任务域）
- 任务状态以 `TaskStatus` 为唯一状态源，页面应按状态码渲染按钮可用性。
- 状态迁移受后端状态机约束，前端需处理 `INVALID_TASK_STATE`。
- 列表与详情之间需要共享任务ID与当前状态，避免多页状态不一致。

## 7. 待确认项
- 是否在“我的任务”列表开启自动轮询；若开启，轮询间隔建议与监控刷新策略协调。
- 审批页是否需要“批量审批”能力（当前后端仅提供单任务审批接口）。
