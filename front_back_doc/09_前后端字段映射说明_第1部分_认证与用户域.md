# 前后端字段映射说明（第1部分：认证与用户域）

## 1. 范围
- 后端来源：`AuthController`、`UserController`、`dto/auth/*`、`dto/user/*`、`dto/Result`。
- 前端范围：登录态、当前用户信息、用户管理列表与增删改查页面。

## 2. 通用响应壳映射（所有接口）

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `code` | `Result.code` | number | 是 | 业务状态码，成功为 `200` |
| `errorCode` | `Result.errorCode` | string | 否 | 失败时用于前端分支处理 |
| `message` | `Result.message` | string | 是 | 展示文案 |
| `data` | `Result.data` | object/array/null | 否 | 业务数据载荷 |


## 3. 认证模块字段映射

### 3.1 登录 `POST /api/auth/login`
请求映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 校验/示例 |
|---|---|---|---|---|
| `username` | `LoginRequest.username` | string | 是 | `@NotBlank`，示例 `alice` |
| `password` | `LoginRequest.password` | string | 是 | `@NotBlank`，示例 `P@ssw0rd` |


响应 `data` 映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `accessToken` | `LoginResponse.accessToken` | string | 是 | 访问令牌 |
| `refreshToken` | `LoginResponse.refreshToken` | string | 是 | 刷新令牌 |
| `tokenType` | `LoginResponse.tokenType` | string | 是 | 通常 `Bearer` |
| `expiresIn` | `LoginResponse.expiresIn` | number | 是 | accessToken 过期秒数 |
| `userId` | `LoginResponse.userId` | number | 是 | 当前用户 ID |
| `username` | `LoginResponse.username` | string | 是 | 当前用户名 |
| `roles` | `LoginResponse.roles` | string[] | 是 | 角色编码列表 |


### 3.2 刷新令牌 `POST /api/auth/refresh`
请求映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 校验 |
|---|---|---|---|---|
| `refreshToken` | `RefreshTokenRequest.refreshToken` | string | 是 | `@NotBlank` |


响应 `data`：与登录接口 `LoginResponse` 完全一致。

### 3.3 登出 `POST /api/auth/logout`
请求映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `refreshToken` | `LogoutRequest.refreshToken` | string | 否 | 传入则一并拉黑 refreshToken |
| `Authorization` | 请求头（`Bearer <accessToken>`） | string | 是 | 后端从请求头提取 accessToken |


响应 `data`：`null`。

### 3.4 当前用户 `GET /api/auth/me`
请求映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `Authorization` | 请求头（`Bearer <accessToken>`） | string | 是 | 登录态校验 |


响应 `data`（`UserResponse`）映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | `UserResponse.id` | number | 是 | 用户ID |
| `username` | `UserResponse.username` | string | 是 | 用户名 |
| `email` | `UserResponse.email` | string | 否 | 邮箱 |
| `status` | `UserResponse.status` | number | 是 | `0=禁用,1=启用` |
| `roles` | `UserResponse.roles` | string[] | 是 | 用户角色列表 |
| `createdAt` | `UserResponse.createdAt` | string | 否 | ISO-8601 时间 |
| `updatedAt` | `UserResponse.updatedAt` | string | 否 | ISO-8601 时间 |


## 4. 用户管理模块字段映射

### 4.1 创建用户 `POST /api/users`
请求（`CreateUserRequest`）：

| 前端字段 | 后端字段 | 类型 | 必填 | 校验/约束 |
|---|---|---|---|---|
| `username` | `CreateUserRequest.username` | string | 是 | `3-50`，`@NotBlank` |
| `password` | `CreateUserRequest.password` | string | 是 | `6-100`，`@NotBlank` |
| `email` | `CreateUserRequest.email` | string | 是 | `@Email`，`@NotBlank` |
| `status` | `CreateUserRequest.status` | number | 否 | 默认 `1` |


响应 `data`：`UserResponse`（结构同 3.4）。

### 4.2 更新用户 `PUT /api/users/{userId}`
路径参数：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `userId` | `@PathVariable userId` | number | 是 | 目标用户ID |


请求（`UpdateUserRequest`）：

| 前端字段 | 后端字段 | 类型 | 必填 | 校验 |
|---|---|---|---|---|
| `email` | `UpdateUserRequest.email` | string | 否 | `@Email` |
| `status` | `UpdateUserRequest.status` | number | 否 | `0/1` |


响应 `data`：`UserResponse`。

### 4.3 删除用户 `DELETE /api/users/{userId}`

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `userId` | `@PathVariable userId` | number | 是 | 删除目标用户 |


响应 `data`：`null`。

### 4.4 用户详情 `GET /api/users/{userId}`

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `userId` | `@PathVariable userId` | number | 是 | 查询目标用户 |


响应 `data`：`UserResponse`。

### 4.5 用户分页列表 `GET /api/users`
请求参数映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 默认值/约束 |
|---|---|---|---|---|
| `page` | `@RequestParam page` | number | 否 | 默认 `1`，最小 `1` |
| `size` | `@RequestParam size` | number | 否 | 默认 `10`，区间 `1-200` |
| `username` | `@RequestParam username` | string | 否 | 用户名模糊过滤 |
| `email` | `@RequestParam email` | string | 否 | 邮箱模糊过滤 |
| `status` | `@RequestParam status` | number | 否 | 状态过滤 |
| `sortBy` | `@RequestParam sortBy` | string | 否 | 默认 `createdAt`，可选 `createdAt/username/email/status/id` |
| `sortDir` | `@RequestParam sortDir` | string | 否 | 默认 `desc`，可选 `asc/desc` |


响应 `data`（`IPage<UserResponse>`）建议前端模型：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `records` | `IPage.records` | UserResponse[] | 是 | 当前页记录 |
| `total` | `IPage.total` | number | 是 | 总条数 |
| `size` | `IPage.size` | number | 是 | 每页大小 |
| `current` | `IPage.current` | number | 是 | 当前页码 |
| `pages` | `IPage.pages` | number | 是 | 总页数 |


### 4.6 分配用户角色 `POST /api/users/{userId}/roles`
路径/参数映射：

| 前端字段 | 后端字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `userId` | `@PathVariable userId` | number | 是 | 目标用户ID |
| `roleIds` | `@RequestBody List<Long> roleIds` | number[] | 是 | 角色ID列表 |
| `expiresAt` | `@RequestParam expiresAt` | string(datetime) | 否 | 角色过期时间 |


响应 `data`：`null`。

## 5. 前端落地约定
- 本部分所有接口均使用统一响应壳，前端先判定 `code`，失败时再按 `errorCode` 分流。
- 登录后以 `tokenType + accessToken` 组装 `Authorization` 请求头。
- 用户状态当前以 `0/1` 为主，若未来扩展锁定态需以前端枚举可扩展方式实现。
